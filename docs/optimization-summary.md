# 优化实施记录

本文描述当前实现，不将历史估算作为性能实测结果。

## 安全边界

- HTML 邮件通过成熟清洗器和 sandbox 文档显示，默认显示远程图片；“设置 → 邮件阅读”可阻止自动加载，并在当前浏览器保存偏好。阻止时仍可逐封临时加载，脚本、危险内容和其他远程资源继续过滤。
- 应用为单人模式，移除注册、用户资料、应用内改密及所有权字段；全部邮箱与邮件属于当前实例。
- 可选环境变量 `ADMIN_PASSWORD` 控制访问：非空时单密码登录，未设置或空时直接使用。签名会话只接受指定算法和有效期，服务重启即失效，无额外签名密钥配置。
- Telegram 使用实例级单例配置，应用服务和通知 worker 通过注入的数据库读取配置；接口只返回掩码，不缓存明文 Token。
- 邮箱凭证和 Telegram Bot Token 从首次保存起以 AES-GCM 密文存储；仅在内存中解密用于访问远端。启动验证凭证密文，明文凭证或密钥错误时拒绝继续启动。环境变量及备份要求见 [部署文档](../DOCKER.md)。

## 最近邮件缓存

- 默认加载 50 封，可在阅读设置中选择 25、50、100 或 200 并保存在当前浏览器。列表与手动刷新使用所选窗口，每账户刷新后保留对应数量的最近邮件，汇总列表按同一上限展示；接口接受 1–200 的 `limit`。正文按需获取并落库，列表不传输正文。
- 正文缓存仅以获取完成标记判断，成功获取的空正文同样缓存；正文与完成标记原子保存。详情读取使用同步时保存的 UIDVALIDITY，不隐式刷新整邮箱来补全旧记录的身份。
- 新邮件、窗口清理、刷新时间和启用通知时的 outbox 任务在同一事务内提交，后台发送成功后删除任务。获取或提交失败时保留原缓存。
- 邮件仅供阅读，不提供删除、已读/未读筛选、批量操作或 IMAP 状态写回；正文使用只读获取，不改变远端已读状态。
- 每个账户分别维护邮箱身份版本和配置版本。更换服务商、用户名或自定义 IMAP 主机/端口时，原子推进版本、清理邮件及待发通知、重置 UIDVALIDITY；密码轮换只推进配置版本，保留同一邮箱的正文缓存。
- 刷新在连接前、提交事务内校验版本；正文读取与落库严格核对邮箱身份和 UIDVALIDITY，账户未记录 UIDVALIDITY 也不跳过比较。旧快照不能借用新配置连接或提交旧结果，相同 UIDVALIDITY 与 UID 不会跨邮箱复用正文。
- 临时登录故障与真正认证失败分别分类；MIME 解析或解码失败不写入已获取标记。正文累计抓取仍限制为 8 MiB。
- 摘要获取必要的 MIME 结构用于附件标识，不下载附件正文。无变化摘要不执行 UPDATE，全文索引只在相关值实际变化时更新。
- 所有 IMAP 连接统一使用应用注入的连接池，包括新增/测试账户的临时连接；dialing、使用中和空闲连接均计入全局 16、每账户 3 的上限，等待可由上下文取消。闲置超过 30 秒的连接在独占借出时检查，失败在原预算内重建；停服显式关闭连接池。
- 全部账户刷新保留 4 个 worker 和每账户 20 秒预算，并受整体 35 秒预算限制；未完成账户返回明确错误。前端刷新请求预算为 45 秒。
- 首次导入和 UIDVALIDITY 变化建立通知基线；扩大窗口补拉的旧 UID 不创建新到邮件通知，真正新增的较大 UID 仍会通知。成功同步过的空邮箱收到第一封邮件仍会通知。禁用通知期间不创建任务，已存在任务暂停至重新启用。
- 通知任务独立保存摘要快照，不受邮件缓存窗口裁剪影响；失败按 10 秒起、最长 1 小时退避重试，重启继续处理。账户删除或身份变化清理旧任务。投递为至少一次：远端接受后、本地确认前崩溃可能造成重复，无法承诺恰好一次。
- 手动转发未缓存正文时先按需获取并校验邮箱身份，正文读取失败则明确报错。
- Gin handler 只解析请求与映射响应，`internal/application` 中的账户、邮件、Telegram 服务承担业务编排；数据库、IMAP 池和 Telegram transport 在主程序组装并显式注入。
- 数据库按当前模型直接创建表和索引，不维护升级版本或历史数据转换；重启保留邮件缓存和通知任务。每次启动验证密文并检查 FTS，一致索引不重建；表初始化、数据库连接与 FTS 检查分文件维护。

## 前端生命周期

- 列表查询取消及版本检查防止旧请求覆盖新筛选结果。
- 邮箱或搜索范围变化关闭当前详情；摘要与详情使用不同类型，正文缓存与当前邮件身份匹配。
- 工作区生命周期隔离不同登录会话，退出或会话失效后取消旧请求，阻止旧响应恢复邮件数据。
- 邮件行支持键盘阅读、搜索、刷新和转发；邮箱账户删除的确认弹窗管理焦点。
- 账户列表使用取消信号和请求代际检查，区分加载、读取失败和成功读取后的空状态；读取失败可重试。
- 表单提交、账户删除及多账户刷新分别维护进行中状态，旧响应不会操作新表单；删除失败保留确认与重试入口。
- 远端同步完成但列表读取失败时明确反馈，保留已展示内容；列表重试不再次触发远端同步。
- 服务商选项来自 `/api/providers`，自定义邮箱新增和编辑均支持 IMAP 主机及端口，预设服务商地址由后端统一维护。
- 账户列表与服务商定义由会话范围的共享 store 管理，路由间复用加载状态；账户修改后统一失效，退出后旧请求不能恢复数据。
- 正文跨路由缓存最多 100 封，按最近访问淘汰；累计正文字符串预算 16 MiB，单封超过 2 MiB 仅保留当前阅读项。预算按 UTF-16 字符串估算，不等同于浏览器总堆内存。

## 性能与验证

保留 SQLite WAL、单连接读写策略、复合索引、可选 FTS5 搜索、IMAP 连接复用、有限并发刷新、路由懒加载及静态资源缓存。列表默认 50 封、最多 200 封，采用普通列表，移除自写虚拟滚动及其尺寸观察与定位状态。

CI 在发布镜像前执行 Go FTS5 测试、前端测试、lint 和构建。Docker 使用与项目匹配的 Go 工具链，不在构建期间修改依赖声明。

FTS 初始化先禁用索引，校验行数、身份及内容并仅在不一致时事务修复，准备成功后启用；失败回退 LIKE 搜索。保留现有索引的正常启动不重复重建。

登录失败受实例级频率限制；HTTP 服务设置请求体、连接及请求头预算并支持优雅关闭。容器后端以普通用户运行，入口脚本仅初始化挂载目录的所有权与权限，日志输出到标准输出与错误。健康检查包含短超时数据库连通性检查。

运行日志记录接口和账户刷新耗时、所有连接（含临时连接）的池容量等待次数及累计时间、数据库连接等待指标、待发通知数和投递结果；不记录邮件主题、正文、凭据或远端 Token。

升级兼容逻辑清理后，使用本地 Go 1.27.3、启用 SQLite FTS5，数据库、应用服务、HTTP handler、邮件缓存与启动入口五个受影响包的 96 项测试通过；前端账户、邮件 store 与收件箱反馈的 49 项测试及 TypeScript 生产构建通过。验证覆盖首次建库、重启保留缓存、明文凭证拒绝启动、错误密钥拒绝启动及 FTS 内容与触发器修复。

隔离浏览器验证全新数据库的空收件箱、当前 RFC3339 日期的列表与正文展示，以及自定义账户的 IMAP 主机和非默认端口回填。验证使用独立端口、数据库和自动生成的密钥，未操作当前运行实例的数据，未向真实邮箱或 Telegram 发送。本轮构建并运行了 Go 服务与前端生产预览，未重新构建 Docker 镜像；容器入口脚本通过 shell 语法检查。

本地合成负载使用 10 个邮箱、500 封带已缓存正文的邮件、4 路并发读取，每种场景各 400 次列表查询；并发场景另执行 40 个真实缓存刷新事务。列表查询与同步服务经过应用层，单连接 SQLite WAL，FTS5 启用，但不包含远端 IMAP 网络耗时。本轮一次测量结果如下，不能解释为生产容量或前后版本性能提升。

| 场景 | 列表 P50 | 列表 P95 | 最大延迟 | 总耗时 |
| --- | --- | --- | --- | --- |
| 仅并发列表查询 | 0.917 ms | 3.994 ms | 9.380 ms | 142 ms |
| 并发列表查询与刷新事务 | 0.957 ms | 28.554 ms | 70.182 ms | 568 ms |

当前规模下保留单连接读写、请求内有界刷新与单体部署；没有测量证据要求拆分读写连接池、引入 IMAP IDLE 或后台同步任务系统。更大规模应结合真实账户数量、远端延迟、数据库等待与接口 P95 重新评估。
