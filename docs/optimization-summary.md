# 优化实施记录

本文描述当前实现，不将历史估算作为性能实测结果。

## 安全边界

- HTML 邮件通过成熟清洗器和 sandbox 文档显示，默认阻止远程图片及其他远程资源；用户可为当前邮件加载远程图片。
- 应用为单人模式，移除注册、用户资料、应用内改密及所有权字段；全部邮箱与邮件属于当前实例。
- 可选环境变量 `ADMIN_PASSWORD` 控制访问：非空时单密码登录，未设置或空时直接使用。签名会话只接受指定算法和有效期，服务重启即失效，无额外签名密钥配置。
- Telegram 使用全局单例配置，查询排除已删除邮箱；升级保留最近更新的完整通知配置。
- 邮箱凭证和 Telegram Bot Token 以 AES-GCM 密文存储；仅在内存中解密用于访问远端。首次启动事务迁移已有数据，密钥错误时拒绝继续启动。环境变量及备份要求见 [部署文档](../DOCKER.md)。

## 最近邮件缓存

- 每账户收件箱严格缓存最近 50 封，汇总列表显示最新 50 封；正文按需获取并落库，列表不传输正文。
- 新邮件、窗口清理和刷新时间在同一事务内提交，通知在提交后发送。获取或提交失败时保留原缓存。
- 邮件仅供阅读，不提供删除、已读/未读筛选、批量操作或 IMAP 状态写回；正文使用只读获取，不改变远端已读状态。
- 升级清理旧删除记录、已删除账户和非收件箱缓存，移除已读、星标、待同步状态及相关索引，裁剪超出 50 封的旧缓存；保留窗口内正常邮件的 ID 和正文。
- 每个账户分别维护邮箱身份版本和配置版本。更换服务商或用户名时，原子推进版本、清理邮件及重置 UIDVALIDITY；密码轮换只推进配置版本，保留同一邮箱的正文缓存。
- 刷新在连接前、提交事务内校验版本；正文读取与落库同时核对邮箱身份，旧快照不能借用新配置连接或提交旧结果。相同 UIDVALIDITY 与 UID 不会跨邮箱复用正文。
- 临时登录故障与真正认证失败分别分类；MIME 解析或解码失败不写入已获取标记。正文累计抓取仍限制为 8 MiB。
- 摘要获取必要的 MIME 结构用于附件标识，不下载附件正文。无变化摘要不执行 UPDATE，全文索引只在相关值实际变化时更新。
- 账户删除与凭证更新失效旧版本连接，保留已经使用最新配置建立的连接；使用中和空闲连接均计入并发上限，等待可由上下文取消。
- 全部账户刷新保留 4 个 worker 和每账户 20 秒预算，并受整体 35 秒预算限制；未完成账户返回明确错误。前端刷新请求预算为 45 秒。

## 前端生命周期

- 列表查询取消及版本检查防止旧请求覆盖新筛选结果。
- 邮箱或搜索范围变化关闭当前详情；摘要与详情使用不同类型，正文缓存与当前邮件身份匹配。
- 工作区生命周期隔离不同登录会话，退出或会话失效后取消旧请求，阻止旧响应恢复邮件数据。
- 邮件行支持键盘阅读、搜索、刷新和转发；邮箱账户删除的确认弹窗管理焦点。
- 账户列表使用取消信号和请求代际检查，区分加载、读取失败和成功读取后的空状态；读取失败可重试。
- 表单提交、账户删除及多账户刷新分别维护进行中状态，旧响应不会操作新表单；删除失败保留确认与重试入口。
- 远端同步完成但列表读取失败时明确反馈，保留已展示内容；列表重试不再次触发远端同步。

## 性能与验证

保留 SQLite WAL、单连接写入策略、复合索引、可选 FTS5 搜索、IMAP 连接复用、有限并发刷新、路由懒加载、虚拟列表及静态资源缓存。

CI 在发布镜像前执行 Go FTS5 测试、前端测试、lint 和构建。Docker 使用与项目匹配的 Go 工具链，不在构建期间修改依赖声明。

FTS 初始化先禁用索引，校验行数、身份及内容并仅在不一致时事务修复，准备成功后启用；失败回退 LIKE 搜索。保留现有索引的正常启动不重复重建。

登录失败受实例级频率限制；HTTP 服务设置请求体、连接及请求头预算并支持优雅关闭。容器后端以普通用户运行，升级时处理原数据目录权限，日志输出到标准输出与错误。健康检查包含短超时数据库连通性检查。

运行日志记录接口和账户刷新耗时、连接池容量等待次数及累计时间、数据库连接等待指标；这些数据用于判断后续性能优化，而非宣称未经测量的提升。

本轮验证使用 Go 1.25.8、SQLite FTS5 与 race detector，数据库测试 fixture 修正后单独复验该包；其余后端包均通过。前端 64 项测试通过，生命周期清理调整后复验相关 24 项测试、lint 和 TypeScript 检查，生产构建通过。浏览器验证桌面错误恢复、390px 移动表单、同步成功但列表读取失败时保留正文，以及只读取列表的重试路径。

最终 Docker 镜像已实际构建并启动：复制 root 所有的旧数据目录后，入口将目录与密钥所有权迁移至 UID/GID 10001，原密钥内容及 `0600` 权限保持，后端以 `app` 用户运行；Nginx 配置检查、健康检查、登录与已有加密 Token 读取通过。停止时 Nginx、后端及容器均以状态 0 退出。本轮没有使用真实邮箱或 Telegram 发送，远端协议边界由隔离协议测试覆盖。

后续吞吐优化需先采集实际账户规模、刷新耗时、连接等待、数据库等待及接口延迟。是否拆分 SQLite 读写连接、引入 IMAP IDLE 或扩大邮件窗口，应依据部署需求和测量结果决定；本文不宣称未经测量的性能提升比例。
