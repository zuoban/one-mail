# 优化实施记录

本文描述当前实现，不将历史估算作为性能实测结果。

## 安全边界

- HTML 邮件通过成熟清洗器和 sandbox 文档显示，默认阻止远程图片及其他远程资源；用户可为当前邮件加载远程图片。
- 应用为单人模式，移除注册、用户资料、应用内改密及所有权字段；全部邮箱与邮件属于当前实例。
- 可选环境变量 `ADMIN_PASSWORD` 控制访问：非空时单密码登录，未设置或空时直接使用。签名会话只接受指定算法和有效期，服务重启即失效，无额外签名密钥配置。
- Telegram 使用全局单例配置，查询排除已删除邮箱；升级保留最近更新的完整通知配置。
- 邮箱凭证以 AES-GCM 密文存储。首次启动事务迁移已有数据，密钥错误时拒绝继续启动。环境变量及备份要求见 [部署文档](../DOCKER.md)。

## 邮件与状态一致性

- 每账户收件箱只缓存最近 50 封，邮件正文按需加载；列表不传输正文。
- 新邮件、状态更新、窗口清理和刷新时间在同一事务内提交，通知在提交后发送。
- 用户期望的已读状态持久化为待同步操作。远端失败保留待同步状态，后续刷新继续处理，避免服务器旧状态覆盖用户操作。
- UIDVALIDITY 与 UID 标识远端邮件，邮箱身份变化时失效旧正文，避免读取错误邮件。
- 临时错误重试耗尽返回失败，正文加载失败不伪装成空邮件。
- 账户删除与凭证更新失效连接，使用中和空闲连接均计入并发上限；等待可由上下文取消。

## 前端生命周期

- 列表查询取消及版本检查防止旧请求覆盖新筛选结果。
- 查询范围变化协调选择集，摘要与详情使用不同类型；状态补丁同步更新详情及缓存。
- 删除提交独立于页面生命周期，刷新排除待删除项；批量失败保留失败选择并准确反馈。
- 无密码模式也建立稳定的工作区生命周期；密码模式退出或会话失效后，旧删除队列无法继续提交。
- 邮件行支持键盘操作，确认弹窗管理焦点。

## 性能与验证

保留 SQLite WAL、单连接写入策略、复合索引、可选 FTS5 搜索、IMAP 连接复用、有限并发刷新、路由懒加载、虚拟列表及静态资源缓存。

CI 在发布镜像前执行 Go FTS5 测试、前端测试、lint 和构建。Docker 使用与项目匹配的 Go 工具链，不在构建期间修改依赖声明。

后续吞吐优化需先采集实际账户规模、刷新耗时、连接等待、数据库等待及接口延迟。是否拆分 SQLite 读写连接、引入 IMAP IDLE 或扩大邮件窗口，应依据部署需求和测量结果决定；本文不宣称未经测量的性能提升比例。
