# 优化执行与验证

目标：完成项目审查提出的优化，按逻辑批次实施；每批提交前检查实际 diff、修复发现的问题并执行相关验证；全部完成后推送。

保留单人实例、只读邮件、SQLite 单连接、邮箱身份版本及凭证加密边界。自动通知的发现时机先通过准确文案说明，不新增未经需求确认的后台轮询。

## 批次与验收

| 批次 | 验收要求 | 状态 |
| --- | --- | --- |
| 1. 依赖与工具链 | 对齐开发、CI、Docker；升级受影响依赖；普通前端测试正常运行；CI 加入漏洞扫描及竞态检查 | 已完成 |
| 2. 账户创建可靠性 | 整体预算明确；重试不创建重复账户；保存与首次同步结果独立；覆盖并发、取消和失败 | 已完成 |
| 3. Telegram 投递 | 完整消息长度与 Markdown 安全；结构化错误、限流等待、失败终态；任务查看、重试、清理 | 已完成 |
| 4. 减少远端请求 | 正文与刷新合并；取消隔离及身份检查；窗口 UID 核对与新增摘要获取；保留远端删除处理 | 已完成 |
| 5. 大正文内存 | Gzip 缓冲复用上限；主题切换复用清洗结果；大正文正确性和内存基准 | 已完成 |
| 6. 开发与行为一致性 | make run 同时启动并回收进程；搜索按字面匹配；明确通知仅在刷新发现新邮件后触发 | 进行中 |
| 7. 可重复验证与文档 | 查询、缓存正文、首次正文、多账户刷新及大正文基准；记录限制；修正和归档过期文档 | 待实施 |

## Review 记录

每批记录实际检查范围、发现及修复、验证结果。提交前均检查暂存区，避免凭据、运行数据和构建产物进入提交。

### 第一批

- 检查工具链版本、CI 相对路径、Docker 双架构镜像标签、锁文件可重现安装、认证初始化及上游修复边界。
- 修复新版 hooks lint 发现的初始化同步状态更新；保留用户主动重试时的失效处理。
- Gin 新引入的 quic-go 仍命中公告，显式提升至 0.59.1。
- typescript-eslint 尚依赖受影响的 minimatch，限定该依赖树覆盖至 11.0.1 及以上；lint 和 TypeScript 构建验证兼容性。
- 普通 `npm test` 的 114 项测试通过，无需 Web Storage 环境开关；lint、构建、`npm ci` 通过；npm audit 为零告警。
- Go 全量竞态测试、vet 通过；Go 1.27.4 上的 govulncheck 为零命中。

### 第二批

- 检查新增账户的完整请求预算、保存后取消、重复请求、并发创建、身份编辑和软删除后的重新添加。
- 账户创建总预算 25 秒，前端等待 35 秒，首次同步仍独立返回警告。
- 连接前检查已保存账户，写入事务内再次检查；实例内写入入口可取消，防止并发新增及编辑产生重复。
- Review 修复：已有重复账户的密码轮换不应被新规则阻止，因此编辑仅在身份变更时检查重复。
- 后端应用层和 handler 的竞态回归、前端账户 API / 表单 / 认证回归通过；增加写入等待取消和历史重复账户密码轮换回归。

### 第三批

- 检查完整消息预算、Markdown 转义、结构化失败策略、任务查询边界、鉴权、关闭配置、重启和限流。
- 永久错误及 10 次尝试后的任务停止自动发送；失败任务支持查看、重试和清理，列表不读出邮件快照。
- Review 修复：仅延迟现有任务会让限流期间新任务继续发送，增加独立的持久等待状态，验证重启、新任务和等待结束后的恢复。
- Review 修复：批次内每次发送前检查配置，关闭或修改通知后停止剩余批次；非 JSON 错误响应保留 HTTP 状态对应的失败策略。
- 后端 Telegram、应用服务、handler、数据库、邮件及 server 竞态回归通过；前端投递记录及设置页测试、lint 和构建通过。

### 第四批

- 正文与账户刷新采用可取消的共享请求；所有刷新入口（含全部账户刷新）经过相同入口，保留账户串行门和全局 4 个远端工作上限。
- 共享工作独立限时；调用者各自取消，全部离开才中止工作，完成或取消后移除记录。刷新键包含数据库、连接池、账户版本、UIDVALIDITY 和窗口，正文键包含邮件及配置版本。
- 同一 epoch 先读取当前窗口 UID，复用不含正文的摘要投影，仅为缺失 UID 取元数据；身份或 epoch 变化不复用，远端删除仍按当前窗口核对。
- Review 增加窗口外元数据拒绝，防止错误远端响应混入缓存；检查旧请求结束不会移除替代请求，旧身份不能提交正文或刷新。
- 共享请求、正文、IMAP、刷新及 handler 的竞态测试通过，覆盖首个调用取消、全部取消、失败重试、键隔离、epoch 切换、UID 异常和未变窗口不取元数据。

### 第五批

- Gzip 池只保留容量不超过 256 KiB 的底层存储，检查 8 MiB 正文压缩还原与缓冲回收。
- HTML 内容与图片权限决定清洗结果，主题只重新包装安全文档；继续保留 CSP、opaque sandbox 和清洗器，不提供未经清洗 HTML 的包装入口。
- Review 修复 Gzip 对 `q=0` 的协商错误，避免将 `notgzip` 识别为 gzip；小响应和未压缩响应也保留编码相关 Vary，并保留原有的多值 Vary。
- middleware/server 竞态测试、邮件 HTML 与设置页测试、lint、构建通过。8 MiB 合成响应基准已运行，记录每请求仍约需正文大小的分配；本批解决池内长期保留，未声称改为流式编码。
